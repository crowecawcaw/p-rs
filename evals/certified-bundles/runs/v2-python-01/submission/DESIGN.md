# Certified change bundle service design

The service stores all durable state in immutable, content-addressed trie nodes and one mutable root record. The root contains pointers for the branch-head map, bundle map, submit idempotency map, and publish outcome map. Trie keys are routed by the hexadecimal SHA-256 of the key; leaves retain the original key and value. Every node is compact JSON, and its content hash names its immutable store key. A write of an already existing blob is harmless, so a caller can retry after losing a blob-write response.

Every state-changing operation reads the current root version, computes replacement trie roots, then compare-and-swaps the single root key. That successful root CAS is the linearization point. Nodes written before a failed CAS are unreachable garbage and do not affect visible state. The caller retries against the new root and rechecks all conditions. Initial heads are built lazily and published by the same root CAS, so concurrent constructors converge on one initial state. No service instance relies on a cached root.

A submit atomically adds both the bundle and its original response to separate tries. Revisions, approvals, and CI results replace the bundle leaf with a path-copied version. A publish checks the request memo first, then checks revision, publication state, readiness, and expected parents in the specified order. Accepted publishing rebuilds the heads trie and replaces the bundle and publish memo leaves in a single root update. Rejections also add their memo in a root update. Thus heads and publish outcomes become visible together. A read captures one root pointer and resolves every requested branch from that immutable snapshot.

The store can contain orphaned immutable blobs after CAS races or interrupted operations; they are safe because roots define visibility. This design assumes the supplied JSON values fit the store's per-value size limit and that SHA-256 collisions do not occur. The trie uses 64 levels, so operations have bounded depth; rebuilding the heads trie at publish costs more store calls than path-copying a single branch but remains bounded for the specified 64-branch tests. The store has no garbage collection, so orphan and superseded blobs accumulate.
