# Certified change bundles design

The service stores immutable, content-addressed snapshots and a single versioned root pointer. A snapshot contains all branch heads and references bounded pages of bundle and publish-request records. Each mutating operation reads the root and snapshot, applies its change to a private copy, writes any new pages and descriptor, then compare-and-swaps the root. A successful root CAS is the operation's linearization point. Competing operations retry from the winning root, so they cannot lose approvals, revisions, CI results, heads, or request outcomes. This provides a single serial order for all state changes and consistent `read_heads`/`get_status` snapshots.

Immutable pages and descriptors can be written before a failed root CAS; those records are unreachable and harmless. If a process crashes after the root CAS but before returning, the state change is durable. Retrying `submit` finds the original bundle record and returns its original revision-one response. Retrying a publish request finds its durable outcome memo before re-evaluating state. Other operations are state-based and retry safely. Initial state is installed lazily by competing compare-and-swaps; only one initialization wins.

Pages are packed below the store's 16 KiB limit, with a 12 KiB target. The descriptor and each individual entity must also fit the limit; this implementation assumes practical benchmark-sized branch and record sets. It rescans the complete logical state for each write, prioritizing correctness and simple recovery over throughput. The shared root is a serialization point. The store's public `read` and `cas` methods are the only persistence and synchronization mechanisms used.
